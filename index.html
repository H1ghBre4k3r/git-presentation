Was ist Git?

Git ist wie eine Zeitmaschine für deinen Code!
  • ✅ Erstelle "Speicherpunkte" (Snapshots) deines Projekts
  • ✅ Gehe jederzeit zu früheren Versionen zurück
  • ✅ Arbeite mit anderen zusammen, ohne Chaos
  • ✅ Sieh genau, wer was wann geändert hat
Zeitmaschinen-Analogie betonen! Git = Sicherheitsnetz für deinen Code

Vorteile:

  • ✓ Grafische Oberfläche
  • ✓ Kommandozeile optional
  • ✓ Integriert in Editor
  • ✓ Visuelles Feedback
  • ✓ Einsteigerfreundlich

Perfekt für Anfänger!

VSCode ✅

3. Setup & Erstes Repository

Bevor wir loslegen 🛠️

Schritt 1: Git konfigurieren

Einmalig pro Rechner! Git muss wissen, wer du bist.

Im Terminal (in VSCode: Strg+Ö):

git config --global user.name "Dein Name"
git config --global user.email "deine@email.de"
git config --global init.defaultBranch main

💡 Warum? Jeder Commit wird mit deinem Namen versehen!

SEHR WICHTIG: Ohne diese Konfiguration wird der erste Commit fehlschlagen! Kurz zeigen: Terminal öffnen, Befehle eingeben Erklären: Name und Email erscheinen bei jedem Commit

Schritt 2: Repository erstellen

Option A: Neues Repository (lokal)

  1. Erstelle einen Projektordner (z.B. mein-projekt)
  2. Öffne ihn in VSCode: File → Open Folder
  3. Source Control Panel öffnen (Strg+Shift+G)
  4. Klick auf "Initialize Repository"
  5. ✅ Fertig! Dein Ordner ist jetzt ein Git-Repository
Live zeigen: Ordner erstellen, VSCode öffnen, Initialize Repository Zeigen: .git Ordner ist nun vorhanden (versteckt)

Schritt 3: Mit GitHub verbinden

GitHub Account erstellen:

  • Gehe zu github.com
  • Sign Up (kostenlos!)
  • Email verifizieren

In VSCode anmelden:

  • Unten links: Klick auf Account-Icon
  • Wähle "Sign in with GitHub"
  • Im Browser anmelden → VSCode autorisieren
  • ✅ Fertig!

Tipp: Einmal anmelden, dann funktioniert Push/Pull automatisch! 🎉

WICHTIG: Anmeldung VOR der ersten Push-Demo! Zeigen: Account-Icon unten links, Sign-In-Flow Beruhigen: Ist einmalig, danach automatisch

Option B: Repository klonen

Du willst an einem existierenden Projekt mitarbeiten?

  1. Gehe zum GitHub-Repository (z.B. von Dozenten geteilt)
  2. Klick auf grünen "Code" Button
  3. Kopiere die HTTPS-URL
  4. In VSCode: Strg+Shift+P → "Git: Clone"
  5. URL einfügen → Zielordner wählen
  6. ✅ Repository wird heruntergeladen!
Kurz erwähnen, nicht zu viel Zeit hier Für Übungsaufgaben oder Gruppenprojekte relevant

Zusammenfassung: Setup ✅

  • Git konfiguriert (user.name, user.email)
  • GitHub Account erstellt
  • VSCode angemeldet bei GitHub
  • Repository erstellt (initialize oder clone)

Jetzt kann's losgehen mit dem ersten Commit! 💪

Kurz zusammenfassen - alle sind jetzt bereit Zeit für Fragen: "Alle soweit?"

Was, wenn ich einen Fehler gemacht habe?

VOR dem Stagen:

  • Rechtsklick auf Datei im Source Control
  • Wähle "Discard Changes"

NACH dem Stagen:

  • Klick auf "-" Icon neben Datei
  • Datei wird zurück zu "Changes" verschoben
  • ✅ Sicher - Änderungen bleiben erhalten

💡 Tipp: Discard nur nutzen, wenn du sicher bist!

Push - Lokale Änderungen hochladen

  1. Commits sind lokal

  2. Push durchführen

  3. Auf GitHub überprüfen

Pull - Änderungen von anderen holen

Szenario: Jemand anderes hat etwas geändert

  1. Datei auf GitHub direkt ändern
    • Simuliert Änderung von Teammitglied
  2. Pull durchführen
    • Auf "..." → "Pull"
  3. Resultat
    • Lokale Dateien sind aktualisiert
Auf GitHub Datei editieren In VSCode pullen und Änderung zeigen

Sync - Der einfache Weg

Sync-Button (unten links in VSCode):

  • Führt Pull UND Push zusammen aus
  • Holt neue Änderungen UND lädt deine hoch
  • Best Practice: Vor dem Arbeiten syncen!
🔄 Sync = Pull + Push
Sync-Button zeigen und erklären Als Best Practice etablieren

Was haben wir gelernt?

  • Push = Deine Commits hochladen
  • Pull = Commits von anderen holen
  • Sync = Beides zusammen
  • Regelmäßig syncen verhindert Probleme!

Workflow erweitert:

7. Konflikte verstehen

Wenn zwei das Gleiche ändern 🔧

Was ist ein Konflikt?

Situation:

  • Du änderst Zeile 5: "Hallo Welt"
  • Jemand anders ändert Zeile 5: "Hello World"
  • Beim Pull: Git weiß nicht, welche Version richtig ist
  • = KONFLIKT (Merge Conflict)

Keine Panik! Das passiert selten am Anfang - und VSCode hilft. 🛟

Beruhigend wirken: Konflikte sind bei Einzelarbeit selten Erst relevant bei Teamarbeit Nicht zu viel Zeit hier - Details in Backup-Folien

Wie VSCode hilft

VSCode zeigt Konflikte visuell:

<<<<<<< HEAD (Current Change)
Hallo Welt
=======
Hello World
>>>>>>> incoming (Incoming Change)

Einfache Optionen:

  • ✅ Accept Current
  • ✅ Accept Incoming
  • ✅ Accept Both

Nach der Wahl:

  • Speichern
  • Stagen
  • Commit erstellen
  • Pushen → Fertig!
NUR theoretisch erklären, keine Live-Demo jetzt Zeit sparen - Details in Backup-Folien Wichtig: Beruhigen, dass es selten passiert

Konflikte vermeiden 💡

Best Practices:

  • Regelmäßig syncen (vor dem Arbeiten!)
  • Oft committen & pushen (nicht tagelang warten)
  • Mit Team absprechen (wer arbeitet woran?)
  • Nicht gleichzeitig an derselben Datei (wenn möglich)

90% der Konflikte vermeidest du so! ✅

💡 Tipp: Ausführliche Demo dazu in den Backup-Folien (bei Interesse)

Prävention ist wichtiger als Lösung! Keine Live-Demo, Zeit sparen Bei Interesse/Fragen: Backup-Folien zeigen Weiter zur Zusammenfassung

Konflikt in VSCode ansehen

Öffne die Datei mit Konflikt:

<<<<<<< HEAD (Current Change)
dozent = Anna Schmidt
=======
dozent = Lisa Müller
>>>>>>> origin/main (Incoming Change)

Was bedeutet das?

  • <<<<<<< HEAD = Deine lokale Version
  • ======= = Trenner
  • >>>>>>> origin/main = Version vom Server
Konfliktmarker genau erklären HEAD = deine Version, origin = Server-Version

Konflikt lösen - Die 4 Optionen

VSCode zeigt über dem Konflikt:

1. Accept Current Change

  • = Deine Version behalten (Anna Schmidt)

2. Accept Incoming Change

  • = Server-Version nehmen (Lisa Müller)

3. Accept Both Changes

  • = Beide Zeilen behalten (beide Dozenten)

4. Compare Changes

  • = Diff-Ansicht öffnen zum Vergleichen

💡 Für dieses Beispiel: Wähle "Accept Current Change" (Anna)

Branch-Basics

Branch = Parallele Version

main:     A ── B ── C ── D
               ╲
feature:        X ── Y
  • Experimentiere ohne das Original zu ändern
  • Merge zurück, wenn fertig

Git vs. GitHub

Git:

  • Versionskontrollsystem
  • Läuft auf deinem Computer
  • Open Source
  • Offline nutzbar

GitHub:

  • Website / Plattform
  • Hostet Repositories
  • Zusatzfeatures
  • Alternativen: GitLab, Bitbucket

Typische Anfängerfehler

  • ❌ Nie committen / Riesige Commits
    ✅ Kleine, häufige Commits stattdessen
  • ❌ Niemals pushen
    ✅ Backup geht verloren - regelmäßig pushen!
  • ❌ Passwörter/Secrets committen
    ✅ .gitignore nutzen!
  • ❌ Konflikte ignorieren
    ✅ Müssen gelöst werden - keine Panik!

Erstes Push: Publish Branch

  1. Publish Branch klicken (Statusleiste/Source Control)
  2. Bei GitHub anmelden und Repository anlegen
  3. Upstream wird gesetzt (origin/main)
  4. Ab dann: Push/Pull/Sync wie gewohnt

Tipp: Sichtbarkeit (privat/öffentlich) wählen, README/Lizenz optional hinzufügen.

Erstes Push live zeigen: Publish Branch → Login → Upstream → normaler Flow.

Änderungen rückgängig machen

Unstaged Dateien:

  • Rechtsklick → Discard Changes
  • Im Diff einzelne Blöcke verwerfen

Staged Dateien: Mit - wieder unstagen

Nach Commit:

  • Commit auswählen → Revert (Gegen-Commit)
  • Amend (letzten Commit anpassen)

Reset ist fortgeschritten → nur erwähnen

Risikoarme Wege: Discard, Revert, Amend. Reset nur nennen.
